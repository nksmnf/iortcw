# Как делать миссии и DLC для RTCW в этом репозитории

Документ отвечает на практический вопрос: можно ли взять историю — книгу,
сценарий, синопсис — и превратить её в набор играбельных миссий на этом форке
Return to Castle Wolfenstein. Ниже: анатомия миссии, полный справочник по языку
скриптов, замеры оригинальной кампании, три производственных маршрута и смета.

Все ссылки на код даны относительно корня репозитория. Одиночная кампания живёт
в дереве `SP/`; мультиплеер (`MP/`) к теме документа отношения не имеет —
см. [MP.md](MP.md).

> **Исходные данные.** Все цифры в документе получены измерением: разбором
> `.bsp` из оригинальных паков в `res/` и подсчётом по таблицам в исходниках,
> а не взяты из внешних руководств по моддингу.

---

## 1. Вердикт: что реально, а что дорого

Миссия RTCW состоит из двух принципиально разных по стоимости частей.

**Сценарная часть — дёшево.** Логика уровня, поведение врагов, диалоги,
катсцены, задачи, музыка, брифинги — это всё простые текстовые файлы с
декларативным синтаксисом. Оригинальная кампания содержит **110 779 строк**
таких скриптов, и они целиком доступны в `res/` как референс. Здесь нет
скрытой сложности: язык состоит из 38 команд для уровня и 82 для персонажей.

**Геометрия — дорого.** Уровень — это скомпилированный `.bsp`: тысячи
выпуклых объёмов (брашей), запечённое освещение, предрасчитанная видимость и
отдельно скомпилированная навигационная сетка для AI. Средняя карта оригинала
— около 6 000 брашей. Исходников `.map` id Software не публиковала, компиляторы
под текущую систему не собраны, а каждая итерация освещения занимает десятки
минут.

Отсюда главный вывод документа: **дешёвый путь к DLC — переиспользовать
геометрию оригинала, заменив в ней весь сценарий целиком.** Это технически
подтверждено (§ 8.1), даёт узнаваемые локации с полностью новым содержанием и
не требует компиляторов карт вообще.

## 2. Анатомия одной миссии

Миссия — не один файл, а комплект из восьми. Ниже — что чем является и чем
производится.

| Файл | Что это | Формат | Чем создаётся |
|------|---------|--------|---------------|
| `maps/<имя>.bsp` | геометрия, освещение, видимость, стартовый набор сущностей | бинарный `IBSP` v47, 17 блоков (`SP/code/qcommon/qfiles.h:549`) | компилятор `q3map2` из `.map` |
| `maps/<имя>_b0.aas`, `_b1.aas` | навигационная сетка для AI, отдельно для малого и крупного габарита персонажа (`SP/code/botlib/be_aas.h:38`) | бинарный | компилятор `bspc` |
| `maps/<имя>.script` | логика уровня: двери, лифты, взрывы, счётчики, задачи | текст | пишется вручную |
| `maps/<имя>.ai` | поведение персонажей: маршруты, реплики, засады, катсцены | текст | пишется вручную |
| `cameras/*.camera` | сплайны движения камеры для роликов | текст | генерируется или пишется |
| `sound/scripts/<имя>.sounds` | псевдонимы звуков уровня и их каналы | текст | пишется вручную |
| `text/EnglishUSA/<имя>.txt` | брифинг миссии и записи в журнале | текст с цветовыми кодами | пишется вручную |
| `levelshots/<имя>.jpg` | картинка загрузочного экрана | JPEG | скриншот из игры |

Всё это упаковывается в обычный ZIP-архив с расширением `.pk3`.

Сущности внутри `.bsp` — это не отдельный файл, а текстовый блок номер ноль
внутри бинарника (`LUMP_ENTITIES`, `SP/code/qcommon/qfiles.h:604`). Именно этот
факт открывает дешёвый производственный маршрут — см. § 8.1.

## 4. Скрипт уровня — `.script`

Управляет неживой частью мира: дверьми, лифтами, поездами, взрывами, задачами,
музыкой, счётчиками.

### 4.1. Структура

Файл — набор блоков, по одному на именованную сущность карты. Имя блока
соответствует ключу `scriptname` сущности в `.bsp`:

```
counter1
{
	spawn
	{
		accum 0 set 0
	}

	trigger action1
	{
		alertentity dark1
		wait 2500
		trigger player cam2
		mu_play sound/music/l_boss
	}
}
```

Внутри блока — обработчики событий; внутри обработчика — последовательность
команд, выполняемых по порядку. `wait` приостанавливает конкретный обработчик,
не блокируя остальные, — это кооперативная многозадачность, на которой держится
вся постановка сцен.

### 4.2. События (`SP/code/game/g_script.c:147`)

| Событие | Когда срабатывает |
|---|---|
| `spawn` | при появлении сущности в мире |
| `trigger <имя>` | по явному вызову `trigger` из любого скрипта |
| `activate <имя>` | игрок или NPC воздействовал на сущность |
| `pain <мин> <макс>` | получен урон в заданном диапазоне здоровья |
| `death` | сущность уничтожена |
| `stopcam` | завершился ролик камеры |

### 4.3. Команды — 38 штук (`SP/code/game/g_script.c:96`)

**Поток управления:** `wait`, `trigger`, `alertentity`, `accum`, `halt`,
`resetscript`, `backupscript`, `restorescript`, `entityscriptname`, `aiscriptname`.

**Движение и анимация:** `gotomarker`, `playanim`, `faceangles`, `attachtotag`.

**Звук и музыка:** `playsound`, `stopsound`, `mu_start`, `mu_play`, `mu_stop`,
`mu_fade`, `mu_queue`.

**Постановка:** `startcam`, `startcamblack`, `print`.

**Задачи миссии:** `missionsuccess`, `missionfailed`, `sethealth`.

**Мультиплеерные (`wm_*`)** — в одиночной кампании не применяются.

### 4.4. Счётчики — `accum`

Единственный механизм состояния в скриптах. Каждая сущность имеет собственный
набор ячеек, адресуемых по номеру. Операции (`SP/code/game/g_script_actions.c`,
идентичный набор в AI-скриптах):

| Операция | Смысл |
|---|---|
| `set <n>` / `inc <n>` | присвоить / увеличить |
| `random <n>` | случайное значение |
| `bitset <бит>` / `bitreset <бит>` | работа с флагами |
| `abort_if_equal <n>` / `abort_if_not_equal <n>` | прервать обработчик по условию |
| `abort_if_less_than <n>` / `abort_if_greater_than <n>` | то же, по сравнению |
| `abort_if_bitset <бит>` / `abort_if_not_bitset <бит>` | то же, по флагу |

Условной ветвистости в языке нет: ветвление выражается через `abort_if_*` в
начале обработчика — приём, которым в оригинале написана вся кампания.

## 5. Скрипт персонажей — `.ai`

Управляет живой частью мира. Синтаксис тот же, но событий и команд больше, и
здесь же живёт особый блок `player` — сценарий самой миссии: её задачи,
стартовая музыка, вступительный ролик.

```
player
{
	spawn
	{
		suggestweapon weapon_mp40
		objectivesneeded 2
		abort_if_loadgame
		mu_start sound/music/l_briefing_2
	}

	playerstart
	{
		mu_fade 0 1000
		trigger player cam0
	}
}
```

### 5.1. События — 25 штук (`SP/code/game/ai_cast_script.c:234`)

| Группа | События |
|---|---|
| Жизненный цикл | `spawn`, `playerstart`, `death`, `fakedeath` |
| Обнаружение | `enemysight`, `sight`, `enemydead`, `enemysightcorpse`, `friendlysightcorpse` |
| Расследование | `inspectbodystart`, `inspectbodyend`, `inspectsoundstart`, `inspectsoundend`, `inspectfriendlycombatstart` |
| Боевые | `pain`, `painenemy`, `attacksound`, `bulletimpact`, `bulletimpactsound` |
| Взаимодействие | `trigger`, `activate`, `blocked`, `avoiddanger`, `statechange` |

Набор вокруг «расследования» — то, на чём держится стелс: труп, найденный
патрулём, поднимает тревогу; услышанный звук заставляет NPC пойти проверить.

### 5.2. Команды — 82 штуки (`SP/code/game/ai_cast_script.c:137`)

**Перемещение:** `gotomarker`, `runtomarker`, `walktomarker`, `crouchtomarker`,
`gotocast`, `runtocast`, `walktocast`, `crouchtocast`, `followcast`,
`explicit_routing`, `teleport`, `parachute`.

**Бой:** `attack`, `noattack`, `fireattarget`, `selectweapon`, `suggestweapon`,
`giveweapon`, `takeweapon`, `setammo`, `setclip`, `knockback`, `lightningdamage`,
`catchfire`, `pushaway`.

**Состояние:** `sethealth`, `setarmor`, `givearmor`, `giveinventory`, `godmode`,
`noaidamage`, `notarget`, `movetype`, `statetype`, `attrib`, `anim_condition`.

**Восприятие:** `sight`, `nosight`, `avoid`, `noavoid`, `headlook`.

**Постановка:** `playanim`, `clearanim`, `playsound`, `startcam`, `startcamblack`,
`stopcam`, `facetargetangles`, `cigarette`, `zoom`, `lockplayer`, `mount`, `unmount`.

**Сценарий миссии:** `objectivemet`, `missionsuccess`, `missionfailed`,
`objectivesneeded`, `foundsecret`, `savegame`, `savepersistant`, `changelevel`,
`endgame`, `abort_if_loadgame`.

**Спавн и управление:** `spawncast`, `trigger`, `alertentity`, `accum`,
`resetscript`, `backupscript`, `restorescript`, `entityscriptname`,
`aiscriptname`, `print`, `cvar`, `deny`, `denyactivate`.

**Музыка:** `mu_start`, `mu_play`, `mu_stop`, `mu_fade`, `mu_queue`.

### 5.3. Атрибуты персонажа — 21 параметр

Команда `attrib <имя> <значение>` меняет поведение NPC прямо во время игры
(`SP/code/game/ai_cast.h:128`). Это позволяет делать новые «типы» врагов из
существующих моделей без единой строки кода на C:

| Атрибут | Диапазон | Смысл |
|---|---|---|
| `RUNNING_SPEED`, `WALKING_SPEED`, `CROUCHING_SPEED` | до 300 | скорости перемещения |
| `FOV` | до 360 | поле зрения |
| `YAW_SPEED` | до 300 | скорость поворота (медленный — как у зомби) |
| `AIM_SKILL`, `AIM_ACCURACY`, `ATTACK_SKILL` | 0–1 | мастерство стрельбы |
| `REACTION_TIME` | 0–1 | задержка реакции на противника |
| `ATTACK_CROUCH`, `IDLE_CROUCH` | 0–1 | склонность приседать |
| `AGGRESSION` | 0–1 | готовность драться до смерти |
| `TACTICAL` | 0–1 | использование укрытий, скрытное преследование |
| `CAMPER` | 0–1 | остаётся на точке спавна |
| `ALERTNESS` | 0–1 | замечает врага на дистанции |
| `LEADER` | 0–1 | способность вести отряд |
| `STARTING_HEALTH` | до 999 | стартовое здоровье |
| `HEARING_SCALE`, `HEARING_SCALE_NOT_PVS` | множитель | острота слуха, отдельно вне зоны видимости |
| `INNER_DETECTION_RADIUS` | по умолчанию 512 | радиус мгновенного перехода в бой |
| `PAIN_THRESHOLD_SCALE` | по умолчанию 1.0 | порог болевой реакции |

Практически: «снайпер-наблюдатель» — это обычный солдат с `CAMPER 1`,
`ALERTNESS 1`, `AIM_ACCURACY 0.9`, `FOV 120`. «Берсерк» — он же с `AGGRESSION 1`,
`TACTICAL 0`, `RUNNING_SPEED 280`. Ассеты те же, ощущение от боя разное.

## 6. Актёры, навигация и сущности

### 6.1. Типы персонажей — 18 (`SP/code/game/ai_cast_characters.c`)

| Категория | Типы |
|---|---|
| Вермахт и СС | `soldier`, `blackguard`, `eliteguard`, `venom`, `frogman` |
| Союзники и мирные | `american`, `partisan`, `civilian` |
| Нежить | `zombie`, `warzombie` |
| Проект «Сверхчеловек» | `protosoldier`, `supersoldier`, `stimsoldier1/2/3`, `loper` |
| Боссы | `helga` (Хельга фон Бюлов), `heinrich` (Генрих I) |

Новый *тип* персонажа требует модели и анимаций — это за пределами скриптования.
Но новый *характер* делается атрибутами (§ 5.3), сменой оружия, скина и головы
(ключи сущности `skin`, `head`, `aiteam`) — и этого достаточно для широкого
диапазона врагов.

### 6.2. Навигация

AI не ищет путь по геометрии напрямую. Работают три слоя:

1. **`.aas`** — предрассчитанная сетка проходимости, два файла на карту: `_b0`
   для обычного габарита персонажа и `_b1` для крупного
   (`MAX_AAS_WORLDS 2`, `SP/code/botlib/be_aas.h:38`). Без неё NPC не сдвинется
   с места. **Для существующих карт она уже есть в паках** — это и делает
   маршрут § 8.1 работоспособным.
2. **`ai_marker`** — именованные точки, к которым скрипт отправляет персонажа
   (`gotomarker`, `walktomarker`). В `dam` их 215, в `village1` — 177. Это
   «раскадровка» патрулей и мизансцен.
3. **`trigger_aidoor`** — подсказки для прохода через двери и узкие места.

### 6.3. Сущности — 147 классов (`SP/code/game/g_spawn.c`)

Для сценариста значимы:

## 7. Камеры, звук, тексты

**Камеры.** Формат `.camera` — сплайн из контрольных точек: отдельная кривая для
положения камеры и отдельная для точки взгляда, плюс длительность:

```
cameraPathDef {
	time 22.000000
	camera_Spline {
		time 22000
		type 2
		name position
		baseVelocity 76.183952
		target {
			granularity 0.025000
			( -1760.000000 -576.000000 -680.000000 )
			...
		}
	}
	target_Spline { ... }
}
```

Формат текстовый и регулярный — камеры можно генерировать программно по
описанию движения, а не расставлять вручную. В оригинале их 210.

**Звук.** `sound/scripts/<имя>.sounds` задаёт псевдонимы, по которым скрипт
вызывает звук через `playsound`:

```
churchn1_1
{
	streaming
	voice
	sound sound/scenaric/church/axis1_poor_josef.wav
}
```

Каналы: `local`, `announcer`, `body`, `voice`, `weapon`, `item`, `auto`;
переключатели `streaming` и `looping`. В паках лежит вся оригинальная озвучка —
включая немецкие реплики врагов, которые переиспользуются без изменений.

**Тексты.** `text/EnglishUSA/<имя>.txt` — брифинг миссии и записи журнала, с
цветовыми кодами вида `^8`:

```
^8MISSION 2: DARK SECRET^8

^8Part 4:The Defiled Church^8

Residents of Wulfburg call this "The Defiled Church"...
```

Каталог локали задаётся именем папки, так что русские брифинги делаются
добавлением своего каталога.

## 8. Три производственных маршрута

### 8.1. Маршрут A — новый сценарий в существующей геометрии

**Суть.** Берём готовую карту оригинала вместе с её `.aas`, полностью стираем
её сценарий и пишем свой: другие враги на других позициях, другие задачи, свои
триггеры, катсцены, музыка, реквизит и завалы из библиотеки готовых моделей.
Локация узнаваема, но играется как новая миссия.

**Почему это работает.** Набор сущностей — текстовый блок внутри `.bsp`. Его
можно заменить целиком, пересобрав файл с пересчётом смещений всех 17 блоков.

**Проверено на практике.** Прототип запущен на `end.bsp`: 27 военных зомби
заменены на venom-солдат, файл пересобран, все блоки целы, 533 сущности
читаются обратно, карта валидна. Ядро инструмента:

```python
def write_ents(src, dst, ents_text):
    d, lumps = read(src)                       # IBSP v47, 17 блоков
    blobs = [d[o:o+l] for o, l in lumps]
    blobs[0] = ents_text.encode('latin-1') + b'\x00'   # LUMP_ENTITIES
    out = bytearray(b'IBSP' + struct.pack('<i', 47) + b'\x00' * (17 * 8))
    new = []
    for b in blobs:
        while len(out) % 4:                    # выравнивание блоков
            out += b'\x00'
        new.append((len(out), len(b)))
        out += b
    for i, (o, l) in enumerate(new):           # переписать таблицу смещений
        struct.pack_into('<ii', out, 8 + i * 8, o, l)
    open(dst, 'wb').write(bytes(out))
```

**Что можно менять:** всех персонажей и их поведение, весь реквизит и мебель,
освещение, звуки, задачи, точки старта, оружие и припасы, поведение уже
существующих дверей, лифтов и взрывных стен, погодные и атмосферные эффекты.

**Чего нельзя:** двигать стены. Форма пространства фиксирована — но её
восприятие ощутимо меняется завалами, баррикадами и перекрытыми проходами из
`misc_model` и `props_*`.

**Стоимость:** компиляторы не нужны, итерация — секунды (пересобрал `.pk3`,
запустил игру).

### 8.2. Маршрут B — новая геометрия

`.map` — текстовый формат: каждый браш описан плоскостями и текстурами. Его
можно писать и генерировать программно, компилировать через `q3map2`, смотреть
результат через скриншоты из игры и итерировать.

Цена: сборка тулчейна, длинный цикл компиляции (освещение на карте масштаба
оригинала — десятки минут) и честное ограничение по качеству — построенная
вслепую с итерациями по скриншотам архитектура будет функциональной и
играбельной, но не такой выразительной, как сделанная человеком в визуальном
редакторе.

### 8.3. Маршрут C — гибрид

Новые компактные карты только для сюжетных роликов (568–2 356 брашей, ~130
строк скрипта — самая дешёвая геометрия в игре) плюс маршрут A для боевых
миссий. Даёт полностью оригинальное повествование при минимальных затратах на
геометрию.

## 10. Смета

Единица оценки — рабочая сессия (1–2 часа сфокусированной работы). Плейтест —
отдельная строка, его делает человек.

### 10.1. Стоимость одной единицы контента

| Единица | Маршрут | Сессий | Плейтест |
|---|---|---|---|
| Сюжетный ролик (ремикс существующей карты) | A | 1–2 | 15 мин |
| Боевая миссия на существующей геометрии | A | 3–5 | 1–2 ч |
| Сюжетный ролик на новой геометрии | B | 4–6 | 15 мин |
| Боевая миссия на новой геометрии | B | 12–20 | 4–6 ч |
| Разовая настройка тулчейна | B | 6–12 | — |

### 10.2. Пакеты

| Пакет | Состав | Геймплей | Сессий | Маршрут |
|---|---|---|---|---|
| Пилот | 1 ролик + 1 короткая миссия | ~15 мин | 4–6 | A |
| Мини-эпизод | интро + 3 миссии + финал | 40–60 мин | 15–25 | A |
| Полный DLC | интро + 5 миссий + 2 ролика + босс | 1,5–2 ч | 35–50 | C |
| Кампания масштаба оригинала | 27 миссий + 5 роликов | 10–12 ч | 300+ | B |

Последняя строка приведена для калибровки, а не как предложение.

### 10.3. Что требуется от заказчика

1. **Материал.** Книга, сценарий или синопсис. Для DLC на пять миссий достаточно
   15–40 страниц или одной повести; адаптация в структуру миссий, задач и
   брифингов — работа исполнителя.
2. **Выбор маршрута** — от него зависит вся остальная смета.
3. **Плейтест.** Темп, сложность и «читаемость» пространства оцениваются только
   игрой. Это единственная незаменимая человеческая часть.
4. **Опционально — озвучка.** Синтез речи или собственная запись. Без неё —
   субтитры плюс существующие немецкие реплики врагов.

## 11. Сборка и запуск DLC

Кампания оригинала линейна и определяется не таблицей уровней, а самими
скриптами: меню запускает первую карту (`exec "spmap cutscene1"` в
`ui/play.menu`), дальше каждая миссия сама вызывает следующую командой
`changelevel <карта> [persistent] [silent]`
(`SP/code/game/ai_cast_script_actions.c:2270`). Флаг `persistent` переносит
инвентарь игрока через переход.

Значит, DLC — это своя цепочка карт со своим стартом, и ей не нужно
вмешательство в код движка.

Структура пакета:

```
mydlc/
  pak0.pk3
    maps/<карты>.bsp, .aas, .script, .ai
    cameras/*.camera
    sound/scripts/*.sounds
    text/EnglishUSA/*.txt
    levelshots/*.jpg
    ui/play.menu          # если нужен свой пункт запуска
```

Запуск: положить каталог рядом с `main` и стартовать движок с
`+set fs_game mydlc`. Отладка — `spdevmap <карта>` вместо `spmap`, чтобы
работала консоль и читы.

Полезные переменные: `g_gameskill` (сложность, `SP/code/game/g_main.c:158`),
`g_episode` (номер эпизода, выставляется скриптом через `cvar`).

## 12. Ограничения

**Требует программирования на C, а не скриптов:**
новые типы AI с собственной боевой логикой, новое оружие, новые механики.

**Требует художника и аниматора:**
новые модели персонажей и анимации — формат `MDS`/`MDC` со своим пайплайном.

**Требует человека:**
оценка темпа, сложности и того, понятно ли игроку, куда идти. Ни один прогон
скрипта этого не покажет.

**Ограничение маршрута B:**
архитектура уровней, построенная без визуального редактора, выйдет крепкой и
играбельной, но по выразительности уступит ручной работе в Radiant.

**Правовое:**
переиспользование ассетов RTCW означает, что DLC требует наличия оригинальной
игры у пользователя — обычная практика для модификаций. Если исходный материал
(книга, сценарий) чужой, для публичного распространения нужны права; для личного
использования вопрос не возникает.

## 13. Чек-лист старта работ

1. Получить исходный материал и согласовать, какая его часть становится DLC.
2. Выбрать маршрут (рекомендация — начать с A).
3. Разложить историю на миссии: место, задача, противник, сюжетный поворот,
   переход к следующей.
4. Подобрать под каждую миссию карту-донор из 32 существующих.
5. Довести инструмент перезаписи сущностей (§ 8.1) до рабочего вида.
6. Сделать пилот: один ролик плюс одна миссия сквозь весь конвейер.
7. Плейтест, разбор, решение о полном объёме.
